# AGENTS.md — AMGCube Website

Guides for anyone (human or AI tool) working on this repository. Read this first.

## Project & deployment

- This is a **Jekyll static site** deployed via **GitHub Pages**.
- Live site: https://amgcube.com (CNAME: `amgcube.com`). GitHub Pages CDN caches ~10 min.
- **Deploy branch: `gh-pages`** — GitHub Pages builds from this branch automatically.
- Local preview: `bundle exec jekyll serve --host 127.0.0.1 --port 4000 --watch`
  (already running during dev; rebuilds automatically on file changes).

## Branch workflow

- Never commit directly to `gh-pages`. Work on a feature branch, then fast-forward merge into `gh-pages` and push:
  `git checkout gh-pages && git merge --ff-only <branch> && git push origin gh-pages`
- Branch naming convention: `optimize-YYYYMMDD-<topic>` / `refine-<page>-<topic>` (avoid throwaway prefixes like `codex/`).
- Keep commits scoped to one logical change with a clear message.

## Architecture

- Pages live in `pages/*.html`; URLs are set via front matter `permalink:`. Sub-pages are NOT directories — they are separate files with nested permalinks (e.g. `pages/can-i-build-site-feasibility.html` → `/can-i-build/site-feasibility/`).
- Shared layouts in `_layouts/` (`home`, `projects`, `project`, `can-i-build`, `can-i-build-detail`, etc.). Partials in `_includes/`.
- Project cards on `/projects/` are generated by the loop in `pages/projects.html`. New/current project data lives in `_projects/*.md`; the Oxley project remains in `_posts/` to preserve its established URL.
- Project detail pages use `_layouts/project.html`, which renders: hero → project specs and timeline → story (`{{ content }}`) → progress gallery → "More work" nav.

### Stylesheets (key files in `_includes/css/`)

- `current.css` — global styles used by the current 11-page site, including the small retained subset of Bootstrap layout/navigation rules.
- `can-i-build-refinement.css` — scoped rules for `/can-i-build/` (inlined into that page via `<style>{% include … %}</style>`).
- `contact-layout.css` — scoped rules inlined into `/contact/`.
- Keep new rules scoped to the current page/component and remove superseded rules instead of accumulating overrides.

### Important GitHub Pages constraint

**GitHub Pages' default build does NOT run custom `_plugins/`.** Use built-in Liquid filters and GitHub Pages-supported features only.

## Content conventions

- Project date fields: `commencement` / `completion` use **YYYY-MM-DD**. Construction duration is auto-calculated (days→months, 1 decimal, trailing `.0` dropped) in `_layouts/project.html` and the list card template.
- Project `layout-summary` uses abbreviations: `2 bed · 2 bath` (middot separators).
- Card CTA is uniformly **"More →"** with `aria-label="More about <project>"` for accessibility.
- Card images: `thumbnail-fit` removed — all cards use `cover`; image container is `aspect-ratio: 16/10`.
- Card metadata uses the editorial structure (not a `<dl>` table): subtitle (location · type) → specs (floor area · layout) → time line (Built/Started).
- Months are abbreviated (`%b`), "approximately" → "approx.".

## SEO / AI search (already deployed)

- `robots.txt` (AI crawlers allowed), `sitemap.xml`, `llms.txt` in repo root.
- `_includes/head.html` carries Open Graph tags, Twitter cards, JSON-LD (`ProfessionalService`) structured data, favicons, canonical.
- Homepage uses `lang="en"` (was accidentally `zh`).
